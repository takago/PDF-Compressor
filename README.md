# PDF Compressor

PDFファイル(数ページ程度の学生レポートなど)をドラッグ＆ドロップするだけで，埋め込みフォントの未使用グリフ削減と画像の再圧縮を行い，ファイルサイズを小さくするWebアプリケーションです．**1 MB以内を目標**にフォントを再サブセット化し，画像の解像度とJPEG品質を段階的に調整します．画像以外のテキスト，リンク，フォームの値は可能な限り維持し，処理後に検証します．1 MBへの縮小や全PDFでの表示の完全一致を保証するものではありません．

**GitHub:** https://github.com/takago/PDF-Compressor

## 主な機能

- フォントの再サブセット化（`subset_fonts()`）と画像のJPEG再圧縮を両方試し，小さくなった結果を採用します．フォント処理後はページ画像の描画比較を行わず，テキスト・フォーム値・リンクの整合性のみを検査します．フォントの表示品質を完全に保証するものではありません．

- PDFをドロップすると自動的にアップロード・圧縮・ダウンロードします．操作ボタンは不要です．クリックによるファイル選択も可能です．
- 単一PDFならPDF（`元ファイル名_compressed.pdf`），複数PDF・フォルダ・ZIPならZIP（`compressed_pdfs.zip`）を返します．サイズが小さくならないPDFは元の内容・ファイル名を維持します．
- フォルダやZIPをドラッグ＆ドロップすると，配下のPDFを再帰的に処理し，相対パスを維持してZIPに格納します．フォルダ内のZIPやZIP内のZIPも最大3階層まで処理します．PDF・ZIP以外のファイルは除外します．
- 複数PDFは同じFIFOキューに登録し，**最大2件を並列**で圧縮します．**待機キューの上限は600件**です．
- 圧縮前後のサイズ・削減率を表示します．詳細診断はデバッグ表示に切り替えられます．
- PyMuPDFが修復して開けたPDFは，一時PDFに再保存して再検証し，問題がなければ画像圧縮を続行します．
- 元PDFは処理完了時に削除し，出力ファイルは原則として処理完了から5分後に期限切れとなります（複数PDFの場合はバッチ全体の完了を基準とします）．

## 動作環境

- Python 3.10以降を想定
- LinuxなどのPythonが動作する環境
- 必要なライブラリ：FastAPI，Uvicorn，PyMuPDF，Pillow，python-multipart（`requirements.txt` に記載）
- GPUは不要です．

## セットアップ

リポジトリを取得します．

```bash
git clone https://github.com/takago/PDF-Compressor.git
cd PDF-Compressor
```

仮想環境を作成して依存ライブラリをインストールします．

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

Webサーバを起動します．**Uvicornのワーカーは必ず1つ**にしてください．これは圧縮処理の同時実行数とは別の設定です．

```bash
uvicorn app:app --host 0.0.0.0 --port 8000 --workers 1
```

サーバ自身からは `http://localhost:8000/`，別のPCからは `http://<サーバのIPアドレス>:8000/` にアクセスします．終了するにはターミナルで `Ctrl+C` を入力します．HTTP運用では通信が暗号化されないため，利用するネットワークとアクセス範囲を適切に制限してください．

## systemdユーザーサービスとして実行する（Linux）

ログインユーザーの権限でPDF Compressorを起動するためのユニットファイルを，`systemd/pdf-compressor.service` に同梱しています．root権限でのシステムサービス登録は必要ありません．

**標準のユニットファイルは，リポジトリを `~/PDF-Compressor` に配置した場合に動作します．** まだクローンしていない場合は，次のようにホームディレクトリで取得し，上記の「セットアップ」に従って `.venv` を作成してください．

```bash
cd ~
git clone https://github.com/takago/PDF-Compressor.git
cd ~/PDF-Compressor
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

すでに別の場所へクローンしている場合は，`systemd/pdf-compressor.service` の `WorkingDirectory` と `ExecStart` を実際の絶対パスに変更してから登録してください．`ExecStart` は仮想環境のPythonを使います．

### サービスの登録・有効化

```bash
mkdir -p ~/.config/systemd/user
cp systemd/pdf-compressor.service ~/.config/systemd/user/
systemctl --user daemon-reload
systemctl --user enable --now pdf-compressor.service
systemctl --user status pdf-compressor.service
```

`enable --now` は，現在のユーザーセッションで起動すると同時に，今後のユーザーsystemd起動時にもサービスを自動起動する設定です．起動後は `http://localhost:8000/` にアクセスできます．

### ログ確認・再起動・停止

```bash
journalctl --user -u pdf-compressor.service -f
systemctl --user restart pdf-compressor.service
systemctl --user stop pdf-compressor.service
systemctl --user disable --now pdf-compressor.service
```

`stop` は今回の実行を停止し，`disable --now` は自動起動も無効化します．ユニットファイルを編集した後は `systemctl --user daemon-reload` を実行してから再起動してください．

**ログアウト後やOS起動直後にも，ログインせずサービスを稼働させる場合**は，管理者権限でlingerを有効化する必要がある場合があります．例えば次のコマンドです（システムの運用規程に従ってください）．

```bash
sudo loginctl enable-linger "$USER"
```

このサービスは `0.0.0.0:8000` でHTTPを待ち受けます．アクセス可能なネットワークを必ず制限してください．`--workers 1` はUvicornのプロセス数であり，PDF圧縮はアプリ内部で最大2並列です．**手動起動したUvicornと同時に動かさないでください**（ポート競合・キューの分離を防ぐため）．また，ユーザーサービスはログインセッションやlingerの設定により稼働期間が変わります．

## 使い方

### PDFを1件圧縮する

1. ブラウザでPDF Compressorを開きます．
2. PDFを画面へドロップします（枠をクリックしてファイル選択も可能です）．
3. 処理が始まり，混雑時は待機状況が表示されます．
4. 完了すると圧縮前後のサイズと削減率が表示され，PDFのダウンロードが自動的に始まります．リンクから再ダウンロードすることもできます（保存期限内のみ）．

### PDFを複数まとめて圧縮する

1. 複数のPDFを一度に選択して，同じドロップ領域に投入します．
2. 全件が共通のFIFOキューに登録され，処理状況が表示されます．
3. 全件の処理が終わると，成功したPDFをまとめた `compressed_pdfs.zip` が自動的にダウンロードされます．

一部のPDFで失敗した場合は，成功したPDFのみZIPに含め，画面に失敗件数と理由を表示します．同名のPDFがあってもZIP内でファイル名が衝突しないように処理します．すべて失敗した場合はZIPを作成しません．ブラウザを開いたままにしてください．

### ZIPアーカイブをまとめて圧縮する

ZIPファイルをそのままドロップすると，内部のPDFを自動的に展開し，通常のFIFOキューに登録します．複数ZIPとPDFを同時にドロップしたり，フォルダ内にZIPを含めたりすることもできます．処理結果は `compressed_pdfs.zip` で返却されます．元ZIP名（拡張子なし）をフォルダ名として使い，ZIP内部のディレクトリ階層を維持します．

例：`Reports.zip` 内の `Class-A/student.pdf` は，返却ZIPで `Reports/Class-A/student_compressed.pdf` になります（圧縮できず元PDFをそのまま返す場合は `student.pdf` です）．入れ子の `inner.zip` は `inner/` ディレクトリとして表現します．

**安全上の制限**：アップロードするPDF・ZIPは1回最大300ファイル，1ファイル512 MB，一括アップロード合計1 GBです．ZIPを展開して得られるPDFは最大300件，展開で読み出すPDF・入れ子ZIPの合計は1 GB以内，ZIPの入れ子は最大3階層，ZIP内のエントリ合計は3000件までです．暗号化・破損ZIP，絶対パスや `../` を含む危険なZIP，シンボリックリンクなどの特殊ファイルは受付しません．展開は一時ディレクトリで行い，元ZIPそのものは返却ZIPには含めません．

ZIP全体の検証・展開でエラーになった場合は，その投入分を登録せずにエラーを表示します．展開後の個別PDF圧縮で失敗したものは，従来どおり成功分だけをZIPに格納します．

### フォルダをまとめて圧縮する

ChromeやEdgeなどの対応ブラウザで，フォルダをPDF Compressorのドロップ領域へドラッグ＆ドロップします．フォルダ内のPDFを自動的に列挙し，既存のFIFOキューで圧縮した後，**元のフォルダ階層を維持したZIP**をダウンロードします．フォルダにPDFが1件しかない場合もZIPを返します．

例えば，次のフォルダをドロップした場合，

```text
Reports/
├── Class-A/
│   └── student001.pdf
├── Class-B/
│   └── student002.pdf
└── README.txt
```

ZIPの中身は次のようになります．

```text
Reports/
├── Class-A/
│   └── student001_compressed.pdf
└── Class-B/
    └── student002_compressed.pdf
```

PDF以外のファイルや空ディレクトリはZIPに含まれません．PDFを複数件そのままドロップした場合は，従来どおりZIP直下にまとめます．フォルダ読み取りにはブラウザのドラッグ＆ドロップ用APIを使用するため，**Chrome・Edge系を推奨**します．ブラウザによってはフォルダのドロップに対応しない場合があります．クリックによる選択は従来どおりPDFファイルのみです．

フォルダ全体・ZIP内のPDFも合わせて最大300件，1ファイル512 MB，一括合計1 GBまでです．相対パスはサーバ側で検証し，`../` や絶対パスなどを拒否します．

### デバッグ表示

通常の利用画面は最小限の情報だけを表示します．画像検出数，圧縮件数，未対応画像などの詳細を確認したいときは，URLに `?debug=1` を付けます．

```text
http://localhost:8000/?debug=1
```

これは**画面表示の切り替え**であり，認証・アクセス制限ではありません．PDFの本文や画像データを診断目的で外部送信する機能ではありません．

## PDFの自動修復

PyMuPDF 1.28.xなどで `code=7: cannot find object in xref` が発生する場合にも，一部の処理で自動回復を試みます．

- **電子署名の安全確認中**に欠落xrefが見つかった場合は，そのxrefを無視して処理を進めず，一度だけPDFの再保存・再読み込みを試します．署名の疑いがある場合や，再検証できない場合は処理を中止します．
- **表示画像のxref照合中**に発生した場合は，参照番号を推測せず表示位置のみ取得し，独立した画像リソースの探索を続行します．読み取れない画像ストリームは変更しません．
- テキスト，フォーム，リンクなどの検証中にエラーが起きた場合は安全のため処理を中止します．欠損オブジェクトを復元できることを保証するものではありません．


PDFの参照表などが壊れている場合，PyMuPDFが読み込み時に修復できることがあります．このアプリケーションは `doc.is_repaired` を検出すると，修復状態のPDFを作業用の一時ファイルに保存し，**再度開いて修復不要と判定されること**を確認してから画像圧縮します．

修復前に読み取れたページ数・各ページのサイズと回転・テキスト・リンク・フォーム入力値を，修復後と比較します．不一致がある場合，修復または圧縮は中止します．電子署名・XFA・パスワード保護PDFは従来どおり対象外です．**自動修復はPDFの外観やフォーム動作の完全一致を保証するものではありません．** PyMuPDFが開けないほど破損しているPDFには対応しません．

- ユーザーの元ファイルは上書きしません．修復用の中間ファイルは圧縮処理の終了時に削除します．
- 修復の有無は結果JSONの `repaired` に記録し，単一PDFのデバッグ表示（`?debug=1`）の備考にも表示します．
- 修復済みPDFは1 MB未満でも再保存したファイルを返します．修復のためファイルサイズが増える場合があります．
- 処理に失敗したPDFでは，修復が不完全だったことや安全性確認の失敗がエラーとして通知されます．

## キューと処理制限

| 項目 | 初期設定 |
| --- | --- |
| Uvicornワーカー | 1 |
| 同時圧縮プロセス | 2件 |
| FIFO待機キュー | 最大600件（処理中2件は別枠） |
| 1回にドロップ可能なPDF | 最大300件 |
| 1ファイルのアップロード上限 | 512 MB |
| 一括アップロード合計 | 1 GB |
| PDF圧縮の処理時間上限 | 120秒／件 |
| 待機時間上限 | 1時間 |
| ダウンロード可能期間 | 完了から5分間（バッチは全件完了から5分間） |

キューが満杯の場合，受付を拒否します．キューはメモリ内で管理しているため，サーバ再起動時に未処理ジョブは復元されません．複数のUvicornワーカーや複数のサーバインスタンスを同じ構成で起動するとキューが独立し，2並列という制限を維持できません．

待機中の元PDFはディスク上に保持されるため，600件の待機を想定する場合はディスク容量を監視してください．残った一時ファイルは起動時と定期清掃で回収します．

## 設定

| 環境変数 | 既定値 | 説明 |
| --- | --- | --- |
| `PDF_OPT_TMP` | `/tmp/pdf-compressor` | 一時ファイルの保存先 |
| `PDF_OPT_MAX_MB` | `512` | 1ファイルあたりのアップロード容量の上限（MB） |

例：一時ファイルの保存先を変更して起動します．

```bash
PDF_OPT_TMP=/var/tmp/pdf-compressor uvicorn app:app --host 0.0.0.0 --port 8000 --workers 1
```

`PDF_OPT_MAX_MB` を変更するときは，`static/index.html` 内のクライアント側の制限・表示も合わせて変更してください．その他のキュー・時間制限の値は `app.py` で定義されています．

## API

| API | 用途 |
| --- | --- |
| `POST /api/compress` | PDF 1件の受付（multipartのフィールド名：`file`） |
| `GET /api/status/{id}` | 単一ジョブの待機・実行・完了・失敗状況 |
| `GET /api/download/{id}` | 処理後PDFのダウンロード |
| `POST /api/batches` | 複数PDF・フォルダ・ZIPの受付（multipartのフィールド名：`files`） |
| `GET /api/batches/{id}` | 一括ジョブの進捗と各ファイルの結果 |
| `GET /api/batches/{id}/download` | 処理後PDFをまとめたZIPのダウンロード |

フォルダの階層を維持したい場合（ZIPを含む場合も）は，`POST /api/batches` に `paths` フォームフィールドを追加し，`files` と同じ順番の相対パス文字列をJSON配列で渡します（例：`["Reports/Class-A/a.pdf", "Reports/Class-B/b.pdf"]`）．この指定がある場合は1件から受け付けます．`paths` を指定しない複数PDFは従来どおりZIP直下に格納します．

アップロード受付時はHTTP 202とジョブID・状態確認用URLを返します．ブラウザは状態確認を繰り返し，完了後にダウンロードします．待機中は接続を長時間維持しません．

## 注意事項

- **通信は暗号化されません．電話番号やパスワードなど機密性の高い情報を含むPDFの利用は避けてください．** 学内ネットワークであってもHTTP通信には傍受・改変の危険があります．
- フォーム値，テキスト，リンクを維持する設計ですが，特殊なPDFや閲覧ソフトでの表示一致は保証できません．重要な文書は変換結果を確認してください．
- 電子署名付き・暗号化・XFA形式のPDFは処理しません．透過マスクなどを含む特殊な画像は再圧縮されないことがあります．
- PDFの構造次第では1 MBを達成できない場合があります．画像を圧縮しても小さくならなければ，元PDFを返します．
- サーバ上の一時ファイルは期限に従って削除されますが，ブラウザにダウンロードされたファイルは削除されません．
- 不特定多数に公開する場合は，コンテナ等による隔離，リクエスト制限，ディスク容量監視，ネットワークのアクセス制御を別途検討してください．

## 出力PDFのファイル名

画面に「元のファイル名で出力する（_compressedを付けない）」チェックボックスを追加しました．既定値はOFFです．

- OFF（既定）：`report.pdf` → `report_compressed.pdf`（圧縮によりサイズが小さくなった場合）．
- ON：`report.pdf` → `report.pdf`．
- フォルダやZIPの階層は維持し，ZIP内のPDFにも同じ設定を適用します．
- ZIP内に同名・同一パスのPDFが重複する場合は，末尾に連番を付けて衝突を避けます．
- 単一・一括APIでは multipart フィールド `keep_original_name=true` を指定すると元名を保持します．未指定なら従来どおりです．

アップロード上限の既定値は1ファイル512 MB，1回の一括合計は1 GB，ZIP展開時の対象ファイルの合計読み出し上限は1 GBです．アップロード上限を増やしたことで，一時ファイルのディスク使用量も増えます．リバースプロキシ側のリクエスト容量制限にも注意してください．
